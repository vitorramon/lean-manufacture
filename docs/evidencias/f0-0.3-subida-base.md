## 1. Primeira tentativa, em `base/` (falhou)

```
$ cd "MOD 3/base"; docker compose -f infra/docker-compose.yml up -d --build

```

As linhas `pull access denied for vf-services` no log são normais: a imagem é construída localmente.

`docker compose logs --tail 80 provisioner` (fim):
```
  File "/app/services/vf_common/src/vf_common/aas/aasx.py", line 95, in _thumbnail
    img = Image.open(path)
PIL.UnidentifiedImageError: cannot identify image file '/repo/docs/screenshots/assets/assembly_cell.png'
27 AAS, 206 submodels, 1100 concept descriptions
```

Causa: os arquivos LFS (PNG, PDF, AASX etc.) ainda são ponteiros (`version https://git-lfs.github.com/spec/v1`). O
provisioner usa os PNG como miniaturas dos AASX. Depois da falha, ficaram em `Created` (não subiram) aas-env, bridge,
edge, maintenance, mes, resolver, supplier, supplier-aas-env, supplier-provisioner e sustainability.
O original `Base/Virtual-Factory` também só tem ponteiros, então não serve de fonte dos objetos.
Instalar o `git-lfs` sem sudo (binário em `~/.local/bin`) foi **negado pelo controle de permissões** desta sessão.
Fica com o usuário: instalar o git-lfs e rodar `git -C base lfs pull`.

Pilha derrubada com `docker compose -f infra/docker-compose.yml down`. O `base/infra/basyx/preload/` ficou só com `.gitkeep`.
