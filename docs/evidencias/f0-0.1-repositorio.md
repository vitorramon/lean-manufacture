git-lfs não está instalado. A tentativa de instalar o binário oficial v3.8.1 (sha256 conferido) em ~/.local/bin, sem sudo, foi negada pelo controle de permissões da sessão. Os 184 arquivos LFS da base continuam como ponteiros; instalar git-lfs (tarefa 0.2) e rodar `git -C base lfs install --local && git -C base lfs pull` (o remoto público https serve LFS).

## Adendo do fechamento da Fase 0 (2026-11-15)

- **LFS baixado na tarefa 0.5**, com o binário `git-lfs` 3.6.1 de usuário (scratchpad da sessão, sha256 conferido):
  `git -C base lfs install --local && git -C base lfs pull` trouxe 184 objetos; `du -sh .git/modules/base/lfs` = 60M;
  `base/godot/products/cylinder/cylinder.glb` começa com `glTF`. Detalhes em `f0-0.5-perfil-reduzido.md`, §0.
- **Pendente:** o git-lfs **não está no PATH** de forma permanente. Conferido no fechamento:
  `git -C base lfs version` → `git: 'lfs' is not a git command`; `~/.local/bin` não tem `git-lfs`. Como
  `filter.lfs.*` e os ganchos LFS estão gravados em `.git/modules/base`, tocar um arquivo LFS do submódulo sem o
  git-lfs no PATH quebra o `git status`/checkout. Ação do usuário: `sudo apt install git-lfs` (ou autorizar o binário
  em `~/.local/bin`).
- `git -C base status -s` vazio no fechamento.
- O vínculo dos submódulos (`.gitmodules`, `base`, `simulador`) é registrado no commit `chore(repo): [0.1] …` do
  fechamento.
- Estado aceito: **parcial** (falta o git-lfs permanente).
