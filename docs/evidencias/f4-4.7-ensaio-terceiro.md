# 4.7 — ensaio do teste do terceiro por agente (2026-11-18)

Ensaio, **não** o teste do RF-A4-03: quem executou foi um agente (`testador-terceiro`) seguindo só o README, num
clone limpo do HEAD local (`git clone --recurse-submodules`, pasta temporária apagada no fim). O teste com um colega
real, com ata, continua pendência do grupo (`docs/pendencias-do-grupo.md`).

## O que falhou

| Passo do README | Resultado | Causa |
| --- | --- | --- |
| 3.2, subida com `--fonte godot` | Pilha saudável e dashboard no ar, mas banco com 0 leituras; `planta.log`: `Could not find type TrainingUi` | Clone limpo não tem `base/godot/.godot` (cache do Godot, ignorado pelo Git da base); o README não mandava importar |
| 3.2, `--parar` em outro terminal | 126 s; o `start.py` continuou vivo e religou dashboard e elos | O `start.py` foi iniciado em segundo plano por shell não interativo, que herda SIGINT **ignorado**; o `--parar` mandava SIGINT |
| 3.4, `twin/t2t/.venv/bin/uals` | `No such file or directory` | Esse ambiente só existe depois de rodar os testes do twin |

## Correções (mesmo dia)

- `start.py` importa o projeto Godot na primeira vez (`importar_planta`), e falha com mensagem clara se o import
  não gerar `base/godot/.godot`. Só gera o cache ignorado; a base não é editada (ADR-0001).
- `start.py` instala explicitamente os handlers de SIGINT e SIGTERM; o `--parar` manda SIGTERM ao `start.py` vivo e
  usa a escada SIGINT → SIGTERM → SIGKILL nos processos que sobrarem.
- README §3.2: import na primeira vez, ~100 s de subida, portas que precisam estar livres, internet na primeira vez.
  README §3.4: `uv run --project twin/t2t uals|uaread|python`.
