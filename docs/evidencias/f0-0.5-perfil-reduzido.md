## 0. Pré-requisito resolvido: objetos Git LFS

A pedido do usuário ("instalar true"), usei o binário de usuário `git-lfs` 3.6.1 já presente no scratchpad da sessão
(sha256 conferido na 0.4), sem sudo e sem instalar nada no sistema:

```
$ export PATH=<scratchpad>/gitlfs/git-lfs-3.6.1:$PATH
$ git -C base lfs install --local     # "Updated Git hooks. Git LFS initialized."
$ git -C base lfs pull
$ git -C base lfs ls-files | wc -l    -> 184
$ head -c 20 base/godot/products/cylinder/cylinder.glb | xxd   -> "glTF...." (antes: "version https://git-lfs...")
$ du -sh .git/modules/base/lfs        -> 60M
$ git -C base status --short | wc -l  -> 0
```

Efeito colateral: o `lfs install --local` gravou `filter.lfs.*` e 4 ganchos (`post-checkout`, `post-commit`,
`post-merge`, `pre-push`) em `.git/modules/base/`. Se algum arquivo LFS do submódulo for tocado, o `git` precisa de
`git-lfs` no PATH (aconteceu uma vez, logo após a importação do Godot: `git-lfs filter-process: 1: git-lfs: not
found`; com o PATH acima o status voltou limpo, e depois funcionou sem PATH). Recomendação: instalar o git-lfs de
forma definitiva (`sudo apt install git-lfs`) ou pôr o binário em `~/.local/bin`.

## 5. Como expressar o perfil sem editar a base (proposta, nada criado)

1. **Lista explícita no `start.py`** (testado aqui): o `start.py` monta
   `docker compose -f base/infra/docker-compose.yml [-f infra/docker-compose.lean.yml] up -d <BASE_SERVICES> <serviços do M3>`,
   com `BASE_SERVICES = ["mqtt", "db", "basyx-config", "provisioner", "aas-env", "aas-ui", "plc-comm", "edge"]`
   e uma opção `--sem-clp` que tira `plc-comm`/`edge` e passa `--vf-backplane=off` ao Godot. Recomendado: é o que foi
   medido e não depende de regras de mesclagem do compose.
2. **`profiles` no override** (`infra/docker-compose.lean.yml` atribuindo `profiles: ["vf-completo"]` aos 19 serviços
   que ficam de fora, para que `up -d` sem perfil suba só o mínimo). **Não testado**; precisa conferir na 1.6 que a
   mesclagem aceita `profiles` em serviço da base e que os caminhos relativos (`..:/repo`, `./basyx/preload`) continuam
   resolvidos a partir de `base/infra/` quando o primeiro `-f` é o da base.
3. Observação: `provisioner`, `plc-comm` e `edge` usam a imagem `vf-services:dev`; numa máquina nova o `up` a
   constrói (na 0.3, 226 s a frio com pull). O `start.py` deve prever esse tempo na primeira execução.
